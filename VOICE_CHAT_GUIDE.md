## What Is LemmyAO?

LemmyAO is a **browser-based client** for the Attorney Online 2 (AO2) roleplaying game. It is written in **TypeScript**, bundled with **Bun**, and runs entirely in the browser. It connects to AO2 game servers using **WebSockets**.

Key facts:
- It is **only a client** — it does not run any server logic.
- All communication goes through a single WebSocket connection to the game server.
- Voice chat is **server-relayed**: your audio never goes directly to other players.
- There is **no WebRTC, no STUN, no TURN, no ICE, no SDP**. Just WebSocket.

---

## Architecture Overview

```
Browser (LemmyAO)
│
│  WebSocket (ws:// or wss://)
│
AO2 Game Server (e.g. Nyathena)
│
│  WebSocket (server → other clients)
│
Other Players' Browsers
```

Every packet — chat messages, character changes, music, **and voice audio** — travels through the server. The server decides who receives what.

### Why No WebRTC?

This is a deliberate design choice. Server-relayed audio means:

1. **Privacy**: Players cannot see each other's IP addresses (no ICE candidate leaks).
2. **Simplicity**: No NAT traversal, no STUN/TURN infrastructure needed.
3. **Control**: The server can moderate, gate, or filter audio frames.

The cost is higher server bandwidth — every audio frame passes through the server twice (once in, once out to each listener).

## The AO2 Packet Protocol

Before looking at voice specifically, you need to understand the base protocol that all messages use.

### Format

Every message follows this text format:

```
COMMAND#arg1#arg2#...#argN#%
```

- `COMMAND` — the packet type identifier (e.g. `HI`, `VS_JOIN`, `VS_FRAME`)
- `#` — field separator
- `%` — packet terminator (marks end of packet)
- Arguments are plain text strings

### Examples

```
HI#abc123def#%
ID#1#webAO#2.9.0#%
VS_FRAME#//8NBJpa9Aa...==#%
```

### Where This Is Implemented

**Sender**: `src/client/sender/sendServer.ts`

```typescript
export const sendServer = (message: string) => {
  client.serv.send(message);  // Sends the raw text packet over WebSocket
};
```

**Receiver / Dispatcher**: `src/packets/packetHandler.ts` reads incoming messages, splits on `#`, looks up the command in the packet registry (`src/packets/packets.ts`), and calls the right handler function.

## Full Connection Handshake

When the page loads, it connects to the server and performs a multi-step handshake before the player can interact. Voice capabilities are negotiated as part of this handshake.

### Step-by-Step

#### Step 1 — WebSocket Opens

**File**: `src/client.ts:175`

```typescript

this.serv.addEventListener("open", this.emit.bind(this, "open"));
```

When the socket opens, `onOpen()` is called. The client changes its state to `Connected` and calls `joinServer()`.

---

#### Step 2 — Client Sends HI

**File**: `src/client.ts:266`

```
Client → Server:  HI#<hdid>#%
```

`hdid` is a hardware device fingerprint generated by FingerprintJS. The server uses this to identify returning players.

---

#### Step 3 — Server Sends HI Back

**File**: `src/packets/handlers/handleHI.ts`

```
Server → Client:  HI#%
```

When the client receives this, `handleHI()` fires and immediately sends two packets:

```
Client → Server:  ID#1#webAO#2.9.0#%
Client → Server:  FL#fastloading#yellowtext#cccc_ic_support#flipping#looping_sfx#effects#%
```

- `ID` tells the server what client software and version this is.
- `FL` tells the server which optional features this client supports.

---

#### Step 4 — Server Sends ID

**File**: `src/packets/handlers/handleID.ts`

```
Server → Client:  ID#<playerID>#<serverSoftware>#<serverVersion>#%
```

This assigns the player their **UID** (unique identifier). Every player on the server has one. UIDs are used throughout voice chat to identify who is speaking.

```typescript
export const handleID = (args: string[]) => {
  client.playerID = Number(args[1]);  // Store our own UID
  // ...
};
```

---

#### Step 5 — Server Sends Game Data

The server sends several large packets containing the list of characters, music tracks, and backgrounds available. These are bulk data loads, not relevant to voice.

---

#### Step 6 — Server Sends VS_CAPS (First Time)

**File**: `src/packets/handlers/handleVS_CAPS.ts`

```
Server → Client:  VS_CAPS#1#1#5#opus#48000#20#4096#%
```

This packet tells the client whether voice is enabled and what the audio settings are. It arrives **before** `DONE`, during the data loading phase. Some clients build their voice subsystem late, so the server sends it again after `DONE` (see Step 7).

Details of this packet are explained in the [Voice Capabilities Negotiation](#voice-capabilities-negotiation) section.

---

#### Step 7 — Server Sends DONE

**File**: `src/packets/handlers/handleDONE.ts`

```
Server → Client:  DONE#%
```

`DONE` signals that the handshake is complete. The client changes state to `clientState.Joined`. The player can now select a character and enter the game.

The server also sends `VS_CAPS` **a second time** here, after `DONE`. This is because some clients build their voice UI only after the handshake completes, and would have ignored the first `VS_CAPS`.

```typescript
export const handleDONE = (_args: string[]) => {
  client.state = clientState.Joined;
  // ... show character select UI ...
};
```

## Voice Chat Deep Dive

Now we get into voice chat. Everything in this section is in `src/voice/voice.ts` and `src/voice/voiceUI.ts` unless otherwise noted.

### What Makes Voice Chat Work

LemmyAO uses three browser APIs:

| API | Used For |
|-----|----------|
| `navigator.mediaDevices.getUserMedia()` | Access the microphone |
| `AudioWorklet` | Process audio in a background thread |
| `AudioEncoder` / `AudioDecoder` (Web Codecs API) | Compress audio to Opus and decompress it back |

These are all standard browser APIs, no libraries needed — except for the Opus codec itself.
Web Codecs' `AudioEncoder`/`AudioDecoder` aren't implemented everywhere (notably, Firefox on
Android/iOS never shipped them, even though Firefox desktop has supported them since v130).
`voice.ts` detects this via `webCodecsSupported()` and, when it's missing, falls back to
`libopus-wasm` — a small WASM build of libopus that does raw Opus packet encode/decode
(`createFrameEncoder()` / `createFrameDecoder()`). Both backends produce/consume the exact same
raw Opus packets over the wire, so a Firefox-mobile peer using the WASM path talks to a
Chrome peer using native Web Codecs transparently. The WASM module is loaded via a dynamic
`import()` so it's only downloaded by browsers that actually need it.

### Voice Capabilities Negotiation

Before any voice activity can happen, the client learns what the server supports via the `VS_CAPS` packet.

#### Packet Format

```
VS_CAPS#<enabled>#<ptt_only>#<max_peers>#<codec>#<sample_rate>#<frame_ms>#<max_frame_bytes>#%
```

#### Example

```
VS_CAPS#1#1#5#opus#48000#20#4096#%
```

This means:
- `1` → Voice is enabled
- `1` → Push-to-talk is required (PTT mode)
- `5` → Max 5 simultaneous speakers per area
- `opus` → Use Opus audio codec
- `48000` → Sample rate: 48 kHz
- `20` → Frame size: 20 milliseconds
- `4096` → Max encoded frame size: 4096 bytes

#### Handler

**File**: `src/packets/handlers/handleVS_CAPS.ts`

```typescript
export const handleVS_CAPS = (args: string[]) => {
  const enabled     = args[1] === "1";
  const pttOnly     = args[2] === "1";
  const maxPeers    = Number(args[3]) || 0;
  const codec       = args[4] || "opus";
  const sampleRate  = Number(args[5]) || 48000;
  const frameMs     = Number(args[6]) || 20;
  const maxFrameBytes = Number(args[7]) || 0;

  installVoiceUI();
  applyVoiceCaps(enabled, pttOnly, maxPeers, codec, sampleRate, frameMs, maxFrameBytes);
};
```

`applyVoiceCaps()` stores these values in the `caps` object. They are used throughout the voice system whenever audio needs to be configured.

#### Default Capabilities (before VS_CAPS arrives)

```typescript
let caps: VoiceCaps = {
  enabled: false,   // Voice is off until server says otherwise
  pttOnly: true,    // Assume PTT required
  maxPeers: 0,

  sampleRate: 48000,
  frameMs: 20,
  maxFrameBytes: 4096,

```

#### What Gets Sent

```
Client → Server:  VS_JOIN#%
```

No arguments — just the command and terminator. The server already knows who you are from your UID.

#### What the Server Sends Back

After receiving `VS_JOIN`, the server sends:

```
Server → Client:  VS_PEERS#101,102,103#%
```

This is the list of **UIDs** of everyone already in the voice room. The client uses this to set up an audio decoder for each one.

**File**: `src/packets/handlers/handleVS_PEERS.ts`

```typescript
export const handleVS_PEERS = (args: string[]) => {
  const csv = args[1] || "";
  const uids: number[] = [];
  if (csv.length > 0) {
    for (const part of csv.split(",")) {
      const n = Number(part);
      if (Number.isFinite(n)) uids.push(n);
    }
  }
  void handleInitialPeers(uids);  // Create one AudioDecoder per peer UID
};
```

`handleInitialPeers()` calls `createRemotePeer()` for each UID in the list. Each remote peer gets its own `AudioDecoder` instance and audio playback pipeline.

#### What the Server Tells Other Players

When you join, the server broadcasts to everyone else in the voice room:

```
Server → other players:  VS_JOIN#<your_uid>#%
```

Those clients' `handleVS_JOIN` fires and they create a decoder for you.

### Audio Capture Pipeline

This is how your microphone audio gets turned into data that can be sent over the network.

#### The Pipeline

```
Microphone (getUserMedia)
     ↓
MediaStreamAudioSourceNode
     ↓
AudioWorkletNode (CaptureProcessor)   ← chunks audio into 20ms frames
     ↓
AudioEncoder (Opus)                   ← compresses each frame
     ↓
Base64 encode
     ↓
VS_FRAME#<base64>#%  →  WebSocket  →  Server
```

#### Step 1: AudioContext Initialization

**File**: `src/voice/voice.ts:237`

```typescript
async function ensureAudioContext(): Promise<AudioContext> {
  audioCtx = new AudioContext({ sampleRate: caps.sampleRate });  // 48000 Hz

  // Register our worklet processors (runs in separate thread)
  const blob = new Blob([WORKLET_CODE], { type: "application/javascript" });
  const url = URL.createObjectURL(blob);
  await audioCtx.audioWorklet.addModule(url);  // Install worklet
  URL.revokeObjectURL(url);

  await audioCtx.resume();  // Requires a user gesture to start
  return audioCtx;
}
```

The `AudioContext` is the root of all Web Audio API processing. It must be created at 48 kHz to match the Opus codec's preferred sample rate.

#### Step 2: CaptureProcessor Worklet

**File**: `src/voice/voice.ts:153` (embedded WORKLET_CODE string)

The `CaptureProcessor` runs in a dedicated audio worklet thread. It receives raw microphone samples and chunks them into **exactly 960 samples per frame** (which is 20ms at 48 kHz).

```javascript
class CaptureProcessor extends AudioWorkletProcessor {
  constructor(opts) {
    super(opts);
    this.frameSamples = 960;  // 20ms × 48000 samples/sec = 960 samples
    this.buf = new Float32Array(960);
    this.pos = 0;
  }

  process(inputs) {
    const ch = inputs[0][0];  // Get audio channel
    for (let i = 0; i < ch.length; i++) {
      this.buf[this.pos++] = ch[i];
      if (this.pos === 960) {
        // Frame is full — transfer to main thread
        const frame = this.buf.slice(0);
        this.port.postMessage(frame, [frame.buffer]);
        this.pos = 0;
      }
    }
    return true;  // Keep running
  }
}
```

Every 20ms, it posts a `Float32Array` of 960 PCM samples to the main thread.

#### Step 3: AudioEncoder (Opus Compression)

**File**: `src/voice/voice.ts:343`

```typescript
const encoderConfig: AudioEncoderConfig = {
  codec: caps.codec,           // "opus"
  sampleRate: caps.sampleRate, // 48000
  numberOfChannels: 1,         // Mono (one channel)
  bitrate: 24000,              // 24 kbps (good quality for voice)
};

encoder = new AudioEncoder({
  output: (chunk: EncodedAudioChunk) => {
    // This fires every time a frame is encoded
    if (!isLocalTransmitting()) return;  // Not transmitting? Discard.

    const buf = new Uint8Array(chunk.byteLength);
    chunk.copyTo(buf);
    const b64 = b64encode(buf);  // Convert binary Opus to base64 text

    if (caps.maxFrameBytes > 0 && b64.length > caps.maxFrameBytes) return;  // Too big? Drop.

    sender.sendServer(`VS_FRAME#${b64}#%`);  // SEND over WebSocket
  },
  error: (e) => console.error("encoder error", e),
});

encoder.configure(encoderConfig);
```

#### Step 4: Connecting the Pipeline

**File**: `src/voice/voice.ts:385`

When a 960-sample frame arrives from the worklet:

```typescript
captureNode.port.onmessage = (ev) => {
  if (!encoder || encoder.state !== "configured") return;
  if (!isLocalTransmitting()) return;

  const pcm = ev.data as Float32Array;

  // Wrap raw PCM in AudioData (required by Web Codecs API)
  const data = new AudioData({
    format: "f32-planar",
    sampleRate: caps.sampleRate,
    numberOfFrames: pcm.length,
    numberOfChannels: 1,
    timestamp: encoderTimestampUs,
    data: pcm,
  });

  encoderTimestampUs += Math.round((pcm.length / caps.sampleRate) * 1_000_000);

  encoder.encode(data);  // Compress to Opus → triggers encoder.output callback
  data.close();
};
```

The encoded Opus bytes come out in the `encoder.output` callback, where they are base64-encoded and sent.

#### Late Arrival Handling

**File**: `src/voice/voice.ts:666`

```typescript
export function handleRemoteAudio(fromUid: number, b64: string): void {
  if (!inVoice) return;
  if (fromUid === client.playerID) return;  // Ignore echoed frames (your own audio)

  const peer = remotePeers.get(fromUid);
  if (!peer) {
    // VS_AUDIO arrived before VS_JOIN for this peer — create on the fly
    if (caps.maxPeers > 0 && remotePeers.size >= caps.maxPeers) return;
    void createRemotePeer(fromUid).then((p) => {
      if (p) feedDecoder(p, b64);
    });
    return;
  }
  feedDecoder(peer, b64);
}
```

If audio arrives before the peer join notification (a race condition), the client creates the peer's decoder on demand rather than dropping the audio.

#### Remote Peer Setup

**File**: `src/voice/voice.ts:439`

Each remote peer gets their own:
- `AudioDecoder` — decompresses Opus back to raw PCM
- `AudioWorkletNode (PlaybackProcessor)` — buffers and plays the PCM
- `GainNode` — allows independent volume control

```typescript
async function createRemotePeer(uid: number): Promise<RemotePeer | null> {
  const ctx = await ensureAudioContext();

  // Create playback worklet (buffers 3 frames to handle jitter)
  const playbackNode = new AudioWorkletNode(ctx, "playback-processor", {
    numberOfInputs: 0,
    numberOfOutputs: 1,
    outputChannelCount: [1],
    processorOptions: { targetQueueFrames: 3 },
  });

  // Volume control
  const gain = ctx.createGain();
  gain.gain.value = vcMuted ? 0 : outputVolume;

  // Connect: playbackNode → gain → speakers
  playbackNode.connect(gain).connect(ctx.destination);

  // Create Opus decoder for this specific peer
  const decoder = new AudioDecoder({
    output: (audioData) => {
      // Decoded PCM → send to playback worklet
      const pcm = new Float32Array(audioData.numberOfFrames);
      audioData.copyTo(pcm, { planeIndex: 0, format: "f32-planar" });
      audioData.close();
      playbackNode.port.postMessage(pcm, [pcm.buffer]);
    },
    error: (e) => console.error(`decoder error for peer ${uid}`, e),
  });

  decoder.configure({
    codec: caps.codec,           // "opus"
    sampleRate: caps.sampleRate, // 48000
    numberOfChannels: 1,
  });

  const peer: RemotePeer = { decoder, playbackNode, gain };
  remotePeers.set(uid, peer);
  return peer;
}
```

#### PlaybackProcessor Worklet (Jitter Buffer)

**File**: `src/voice/voice.ts:196` (embedded WORKLET_CODE)

The `PlaybackProcessor` worklet maintains a small queue of decoded frames to smooth out network jitter:

```javascript
class PlaybackProcessor extends AudioWorkletProcessor {
  constructor(opts) {
    super(opts);
    this.targetQueue = 3;  // Buffer 3 frames = 60ms of audio
    this.queue = [];
    this.primed = false;
  }

  process(_inputs, outputs) {
    const out = outputs[0][0];

    if (!this.primed) {
      if (this.queue.length < 3) {
        out.fill(0);  // Silence while buffering
        return true;
      }
      this.primed = true;  // Buffer is full, start playing
    }

    if (this.queue.length > 0) {
      // Copy next frame to output
      const frame = this.queue.shift();
      out.set(frame.subarray(0, out.length));
    } else {
      // Buffer underrun — go back to priming mode
      out.fill(0);
      this.primed = false;
    }
    return true;
  }
}
```

The 3-frame (60ms) buffer means audio can be delayed by 60ms before playback starts, but once started it can tolerate 60ms of network jitter without glitching.

#### Decoding a Frame

**File**: `src/voice/voice.ts:682`

```typescript
function feedDecoder(peer: RemotePeer, b64: string): void {
  const bytes = b64decode(b64);  // base64 → Uint8Array
  if (bytes.byteLength === 0) return;
  if (peer.decoder.state !== "configured") return;

  const chunk = new EncodedAudioChunk({
    type: "key",
    timestamp: 0,
    data: bytes,
  });
  peer.decoder.decode(chunk);  // Opus → PCM (triggers decoder.output callback)
}
```

The decoded PCM lands in the `AudioDecoder.output` callback, which posts it to the `PlaybackProcessor` worklet, which queues it and plays it to the speakers.

| `ID` | `ID#<uid>#<software>#<version>#%` | Assigns player UID |
| `FL` | `FL#...#%` | Feature list ack |
| `DONE` | `DONE#%` | Handshake complete |
| `VS_CAPS` | `VS_CAPS#<enabled>#<ptt>#<maxPeers>#<codec>#<sampleRate>#<frameMs>#<maxBytes>#%` | Voice capabilities |
| `VS_PEERS` | `VS_PEERS#<csv_uids>#%` | Current voice room roster |
| `VS_JOIN` | `VS_JOIN#<uid>#%` | A peer joined voice |
| `VS_LEAVE` | `VS_LEAVE#<uid>#%` | A peer left voice (or you were kicked) |
| `VS_SPEAK` | `VS_SPEAK#<uid>#<0_or_1>#%` | Peer speaking state changed |
| `VS_AUDIO` | `VS_AUDIO#<from_uid>#<base64_opus>#%` | Audio frame from a peer |

## Glossary

| Term | Definition |
|------|-----------|
| **AO2** | Attorney Online 2 — the game protocol this client implements |
| **AudioContext** | Web Audio API root object; manages all audio processing |
| **AudioDecoder** | Web Codecs API: decompresses encoded audio (Opus → PCM) |
| **AudioEncoder** | Web Codecs API: compresses raw audio (PCM → Opus) |
| **AudioWorklet** | Audio processing that runs in a separate high-priority thread |
| **Base64** | Encoding scheme that converts binary bytes to text characters |
| **hdid** | Hardware Device ID — a fingerprint of the player's browser/machine |
| **ICE / STUN / TURN** | WebRTC infrastructure for peer-to-peer connections (NOT used here) |
| **Jitter Buffer** | Queue of frames that absorbs network timing variation |
| **Mono** | Single audio channel (vs. stereo which has left + right) |
| **Opus** | Audio codec used by Discord, WebRTC, and this system |
| **PCM** | Pulse-Code Modulation — raw uncompressed audio samples |
| **PTT** | Push-to-Talk — microphone only active while a key is held |
| **Sample Rate** | How many audio samples per second (48,000 = 48 kHz) |
| **Server-Relayed** | All data goes through the server, never peer-to-peer |
| **UID** | Unique ID assigned to each player by the server |
| **WebSocket** | Bi-directional text/binary connection over TCP |
| **WebRTC** | Browser peer-to-peer technology (NOT used here) |
